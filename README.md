# بوابة السندباد الداخلية — ملفات التصميم

البوابة الداخلية لموظفي شركة نافذة صحار للتجارة – السندباد (الوكيل الحصري لـ OPPEIN في سلطنة عُمان)، ومعها **لوحة تحكم** للموظفين الإداريين.

> **مهم:** هذا نموذج تصميم تفاعلي (UI) فقط. كل البيانات وهمية وتُحفظ في متصفحك وحده (localStorage وIndexedDB). لا يوجد خادم ولا بريد حقيقي، ولا تُرسل أي بيانات لأي مكان.

## التشغيل

شغّل الفولدر عبر خادم محلي حتى تعمل البوابة ولوحة التحكم معًا وتتشاركا البيانات:

```bash
cd sindbad-portal-design
python3 -m http.server 8000
# البوابة:       http://localhost:8000
# لوحة التحكم:   http://localhost:8000/dashboard/
```

افتح البوابة ولوحة التحكم في تبويبين: أي طلب أو رسالة أو خبر يظهر في التبويب الآخر فورًا.

## ما الجديد في البوابة

- **تسجيل الدخول وإنشاء الحسابات:** يسجّل الموظف بياناته، ويحصل تلقائيًا على بريد رسمي بالصيغة `الاسم.العائلة@sindbad.om`. ينتظر الحساب تفعيل الموارد البشرية (يمكن إلغاء هذا الشرط من الإعدادات).
- **البريد الداخلي @sindbad.om:** صفحة بريد كاملة فيها الوارد والمميزة والمرسلة والأرشيف والمحذوفات، مع المحادثات والردود والمرفقات والبحث. يراسل الموظف أي زميل أو أي قسم (`hr@` و`management@` و`it@` وغيرها)، وعدد الرسائل غير المقروءة يظهر في الهيدر.
- **الطلبات الإلكترونية:** إجازة، إذن انصراف، سلفة، شهادة أو خطاب، وحساب لموظف جديد. كل طلب يُقدَّم بنموذج كامل وتظهر حالته وسجله ومسار اعتماده، ويُخصم رصيد الإجازة السنوية تلقائيًا عند الاعتماد. كل طلب له محادثة في البريد.
- **شاشات الدخول والتسجيل (مبسطة):** حقول أوضح بارتفاع موحد، وإظهار كلمة المرور، و«نسيت كلمة المرور؟» و«تذكرني». إنشاء الحساب صار خطوتين (بياناتك ← العمل وكلمة المرور) مع مؤشر لقوة كلمة المرور. شاشة دخول لوحة التحكم بنفس الأسلوب، ومنها رابط للتسجيل من البوابة (`index.html#register`).
- **حسابي:** صورة الموظف وبياناته، تغيير كلمة المرور، ورصيد الإجازة.
- **المحتوى مأخوذ من لوحة التحكم:** الأخبار، المكتبة، الأنظمة، الفروع، شرائح الرئيسية، موظف الشهر، صفحة الشركة، وبيانات التواصل.

## التحديث الثاني: التركيز على مهام الموظف والاعتمادية

- **التنقل (معاد تصميمه):** خمسة أقسام بدل قائمة طويلة: الرئيسية · مساحتي (البريد، طلباتي، حسابي) · الشركة (الأخبار، الزملاء، عن الشركة، الهوية) · المعرفة (المكتبة، اللوائح، مركز المبيعات) · الأنظمة.
  - على الشاشة الكبيرة: قوائم منسدلة لكل عنصر فيها أيقونة ووصف قصير، وعدادات البريد والطلبات. على يمين الهيدر: زر بحث، والبريد، والتنبيهات، والحساب. اللغة والوضع الداكن موجودان في قائمة الحساب.
  - على التابلت: قائمة جانبية مقسمة بنفس الأقسام، وفي أعلاها بطاقة المستخدم وأزرار اللغة والوضع الداكن، وفي أسفلها لوحة التحكم وتسجيل الخروج.
  - على الموبايل: هيدر أنحف وشريط سفلي بسيط ملاصق لأسفل الشاشة فيه الرئيسية وطلباتي والبريد والزملاء، وزر «المزيد» يفتح القائمة الجانبية.
  - زر «رجوع» في المتصفح يعمل بين الصفحات.
- **مساحة عملي:** في الرئيسية، فيها الرسائل غير المقروءة، والطلبات قيد المتابعة، ورصيد الإجازة، ودليل الزملاء.
- **دليل الزملاء (`#directory`):** بحث بالاسم أو الوظيفة أو الفرع، وفلتر بالقسم، وزر مراسلة لكل زميل ولكل قسم.
- **ساعات العمل والإجازة الأسبوعية:** تُقرأ من إعدادات لوحة التحكم بدل الأرقام الثابتة.
- **قواعد الطلبات:** أيام العمل تُحسب على الخادم التجريبي وفق الإجازة الأسبوعية. ممنوع تجاوز رصيد الإجازة أو تقديم إجازتين متداخلتين. الرفض يحتاج سببًا. الانتقال بين الحالات مقيّد (جديد ← مراجعة ← اعتماد أو رفض، وإعادة الفتح ترجع الرصيد بدقة). كل عملية تتم كاملة أو تُلغى كاملة.
- **خصوصية البريد:** كل صندوق يرى رسائله فقط. الرد على تعميم يذهب لمرسله وحده ولا يصل لكل الموظفين. يظهر المستلمون فوق خانة الرد، ولا تضيع الرسالة أو مرفقاتها إذا فشل الإرسال.
- **لوحة التحكم:** كل موظف إداري يرى نشاطات نطاقه فقط. الاعتماد يتم من نافذة الطلب بعد مراجعته، لا بضغطة سريعة. الاستيراد يرفض أي ملف غير صالح دون أن يمس البيانات الحالية.
- **إمكانية الوصول:** أسماء واضحة للأزرار، وتنقل كامل بلوحة المفاتيح، واحترام إعداد تقليل الحركة.

## لوحة التحكم (`dashboard/`)

- **نظرة عامة:** أهم المؤشرات مع اتجاهها، حركة الطلبات خلال 30 يومًا، توزيع الطلبات حسب الحالة، الطلبات التي تنتظر القرار (اعتماد أو رفض بضغطة)، أحدث الرسائل، توزيع الموظفين على الفروع، وآخر النشاطات.
- **البريد:** صناديق الأقسام حسب الصلاحية، مع البريد الشخصي، وقوالب رد سريعة، وتعميم لجميع الموظفين (للمدير والموارد البشرية).
- **الطلبات:** عرض كجدول أو كلوحة مراحل، مع فلاتر للحالة والنوع والفرع، وتفاصيل كاملة للطلب. القرار وملاحظة المسؤول يصلان للموظف على بريده. التصدير بصيغة CSV.
- **الموظفون:** تفعيل التسجيلات أو رفضها، إضافة موظف، تعديل البيانات والصلاحية والحالة ورصيد الإجازة، إعادة تعيين كلمة المرور، والتصدير.
- **المحتوى:** إضافة وتعديل وحذف كل محتوى البوابة: الأخبار بصورة غلاف ومسودات وتثبيت، المستندات مع رفع ملف جديد مكان القديم، الأنظمة، الفروع، شرائح الرئيسية مع ترتيبها، موظف الشهر، صفحة الشركة، والتواصل والروابط.
- **النظام:** سجل النشاط، وإعدادات البوابة، وصناديق الأقسام، ومصفوفة الصلاحيات، وتصدير البيانات التجريبية واستيرادها وإعادتها للبداية.

## الربط بخادم حقيقي لاحقًا

كل التعامل مع البيانات يمر عبر كائن واحد هو `SB` في `assets/js/store.js`، ومنه: `auth` و`mail` و`req` و`files` و`list` و`put` و`remove` و`cfg`. عند التطوير الفعلي:

1. نفّذ نفس الدوال لتتصل بواجهة برمجية (API) أو بـ Firebase أو Supabase. الواجهتان لن تحتاجا لأي تعديل تقريبًا.
2. سجّل الدخول عبر الخادم (أو Microsoft 365 / Google Workspace)، ولا تُبقِ كلمات المرور في المتصفح.
3. اربط البريد بخادم بريد فعلي للنطاق `sindbad.om` (مثل Microsoft 365 أو Google Workspace أو Zoho)، واجعل صفحة البريد واجهة له.
4. احذف دالة `seed()` والحسابات التجريبية.
